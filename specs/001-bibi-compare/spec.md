# Feature Spec: 001-bibi-compare（比比 · AI维度对比管线）

**来源**：`PRD-AI维度对比.md`（F1-F39 拍板事实库）
**范围声明**：本 spec 只覆盖**业务管线（抽取/汇编/渲染）的真实实现**——把 demo 报告页从硬编码数据升级为「mock笔记 → 抽取 → 汇编 → 渲染」的真实代码链路。检索层/SKU发现/真实LLM调用均为 mock 适配器（同签名，F36/F37）。

## 1. 背景与目标

demo 只验证两件事：**抽取质量 + 交互形态**（F37）。交互形态已由 6 页面 demo 验证；本 spec 补齐前者——`report.html` 当前 ROWS 为硬编码，管线逻辑（分群/样本标注/差异排序/折叠/报备降权/幻觉校验/中立红线）没有真实代码承载，无法评测。

**目标**：维度选择完成后，报告页数据由真实管线产出：mock笔记库 → 抽取层（真实 prompt + mock LLM 适配器）→ 汇编层（全真实规则代码）→ 渲染层。

## 2. 用户故事与验收标准

### US1 生成对比报告（P1 · MVP）
用户勾选 2-3 件 SKU 与若干维度后，系统产出对比报告 JSON 并渲染为表格。
- AC1.1 报告含每个所选维度的行；客观维度（价格/重量/容纳人数）由 SKU 结构化参数直读（规则层，不经 LLM，PRD §2.1）。
- AC1.2 客观行事实标签由代码计算：最低价=参与对比 SKU 中价格最低者；最轻=重量最轻者。**禁止「最优/更值」等评价词**（F30）。
- AC1.3 2 件与 3 件 SKU 均可生成，行/列自适应。
- AC1.4 追加维度（＋号）与初始维度走**同一条管线**（F38：demo 直接填预设维度，但必须经管线产出，不许旁路硬编码）。

### US2 抽取：忠实转述（P1）
抽取层从笔记产出证据元组（维度/结论/人群/证据强度/原文片段/note_id，PRD §4.3）。
- AC2.1 抽取器系统提示词 = PRD §3.2「忠实转述者」草案原文 + JSON 输出格式约定。
- AC2.2 LLM 以**可注入适配器**形式接入（`complete({system,user})` 签名）；demo 用 mockLLM（确定性查表返回），未来换真适配器零改业务代码。
- AC2.3 笔记未提及的维度不产出元组（禁止填充，铁律3）。

### US3 汇编：证据陈列师（P1）
汇编层把元组汇编为对比行，全部规则可测：
- AC3.1 **分群**：同 SKU 同维度不同人群结论分组陈列，不求平均不择优（F19）；人群标签冲突双方均为「通用」时并列展示并标「证据存在分歧」（PRD §5）。
- AC3.2 **合并**：同 SKU+维度+人群+相同结论的元组合并为一组：n=证据数，lvl=组内最强证据强度（实测视频>实测图文>开箱>观点陈述，F18）。
- AC3.3 **样本不足**：组内 n<3 → lack 标注（显著灰标）。
- AC3.4 **差异优先**：diff=参与对比的全部 SKU 均有该维度证据 且 跨 SKU 结论存在差异（F17）。行排序：客观行置顶（客观上/主观下，F31）→ 主观行内 diff 行置前 → 无 lack 行优先 → hot_rank。
- AC3.5 **折叠**：未入选的知识表维度中，所有 SKU 结论完全一致者折叠展示（如防晒「三款结论一致」）。
- AC3.6 **无数据**：某 SKU 某维度零元组 → 单元格「无数据」，禁通用知识填充（F30）。
- AC3.7 **报备降权**：is_reported 元组仍在组内计数，但证据列表排序沉底（F11）。
- AC3.8 **追加池**：plusPool = 知识表顺序 − 已选维度 − 折叠维度。

### US4 质量护栏（P1）
- AC4.1 **幻觉校验**（§5）：元组结论与原文片段无共同关键词（分词后零交集）→ 静默丢弃 + 计数；丢弃率>10% 触发提示词 review 标记。
- AC4.2 **中立红线**（F30）：结论含推荐性表述（建议买/推荐/更值得/最优/闭眼入等词表）→ 拒收 + 计数（violation，导购倾向检出）。
- AC4.3 **溯源完整**：每条元组 snippet 必须是其所引笔记原文的子串；不满足即丢弃。

### US5 人群筛选联动（P2）
- AC5.1 行级 crowds = 该行全部人群标签归一化（露营新手→新手、通勤党→通勤、158/170+ 保留；通用/无对应 chip 的标签不进 crowds）。
- AC5.2 筛选 chip 按人群键匹配行 crowds，命中行置前、未命中灰显（现有交互不变）。

## 3. 约束

- 纯前端 + Node 可测：模块用 UMD 包装（浏览器 script 标签 / Node require 双端加载），无构建步骤（本机仅有 Node）。
- mock 数据：帐篷 12 篇笔记（PRD §4.2.1 例子A），snippet 均为笔记原文子串。
- 性能：mock 管线同步毫秒级返回（PRD §5「demo：12篇mock笔记秒级返回」）。

## 4. 范围外

真实检索与 SKU 发现（点点基建）、真实 LLM 服务接入、西装例子B、后端 API 落地（六接口仅以管线函数同签名预演）、讨论层/单品报告（v2）。
